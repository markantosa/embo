v3.4 SUMMARY OF CHANGES — this revision is a hardware-hardening and naming-discipline pass, prompted directly by (a) a live TMC2209 hot-swap incident on the fabricated v2.51 board that sparked and left the ESP32 module overheating on every subsequent power-up, and (b) the recognition that this document's passives had never been given individual reference designators, which had already let one BOM gap (the Tx/Rx bias-divider resistors) go uncounted. (1) FULL REFERENCE-DESIGNATOR NAMING PASS: every passive on the board — resistors, capacitors, diodes, the inductor, both LEDs — now has an explicit, unique ref designator assigned at the point it's introduced, plus a master lookup table (§12.3) and a "which reel do I actually need" non-standard-value quick reference (§12.2), specifically so a stray label like "input ceramic" can never again refer to the wrong physical part. (2) ON-BOARD BACKSTOP FUSE, F2: a second, on-board 8A SMD slow-blow fuse (Littelfuse Nano2 452-series) added in series after Q1, sized deliberately ABOVE the primary inline T5A so it never coordinates against it in a normal fault — it exists only to catch the case where the inline holder is empty, bypassed, or mis-fitted. See §2.1. (3) TMC2209 UART PIN CORRECTION: physical inspection of the actual MKS V2.0 module silkscreen found pin 5 (not pin 4) is the direct PDN_UART node, with the module's own R8 separator sitting between pin 5 and pin 4 — the OPPOSITE of what every version through v3.3 documented (inherited from generic third-party SilentStepStick writeups, not this specific module). Jumper default flipped accordingly on both U5 and U6. See §7.3. (4) TMC2209 MS1/MS2 ADDRESS JUMPERS: both U5 and U6 gain 1×3+shunt jumpers on MS1 and MS2 (4 headers total), making the two modules fully interchangeable across UART addresses 0–3 instead of hardwired at fixed addresses. See §7.2. (5) GPIO SHORT-FAULT PROTECTION: following the hot-swap/spark incident, a 220Ω series resistor is now placed on every ESP32-to-TMC2209 control line (STEP, DIR, EN, PDN_UART, MS1, MS2 — ×2 modules = 12 resistors) at the socket boundary, limiting fault current into the GPIO's internal clamp structure if a module is ever seated off-axis or hot-swapped again. A procedural line is also added to §13: power off and allow VM bulk caps to discharge before inserting/removing any TMC2209 module. See §7.6 and the fabricated-board incident note in §7.1. (6) UAS TX/RX HARDENING: IC1's Tx gain resistor (RfO1_1, 390Ω) changes footprint from SMD to THT for field gain adjustment (fixed value retained — no trim potentiometer, to avoid accidental drift); the Rx chain gains an explicit interstage AC-coupling network between stage 1 and stage 2 (CouAC_C2 + RbiasO2_3/RbiasO2_4) to block op-amp offset accumulation ahead of the ×10.1 second stage. See §5.2 and §5.5. (7) COMPONENT PACKAGE/PROCUREMENT CHANGES: TMC2209 VM bulk caps change from 100µF/50V THT radial to 100µF/50V SMD radial, 8mm height, placed beside (not under) each module socket for physical clearance; screw terminal J14 changes from 3.5mm to 5.0mm pitch for higher current margin and heavier-gauge wire; boot/reset buttons change from SMD 6×6 tactile to THT 6mm tactile for rework durability — mechanical footprint to be verified against the actual part's drawing, not the KiCad footprint name alone. See §6.3, §9, §12. (8) 24V POWER LED WIRED: LED_pwr + new R_LEDpwr (10kΩ) now explicitly wired in §2, tapping the PROTECTED rail (Q1 Source) rather than raw input, so the indicator only lights when Q1 is actually passing current correctly. (9) LIVE HARDWARE STATUS CARRIED FORWARD (open, not resolved by this revision): the v2.51 fabricated board's original LM2596 buck fault (external buck module workaround in place, U2 never bench-verified standalone) and the TMC2209 hot-swap short (ESP32 module suspected damaged, diagnosis in progress) are both still open — see §13.

1. SYSTEM OVERVIEW, POWER RAILS, AND MASTER GPIO MAP
====================================================================================

1.1 Overview
------------
EMBO is a closed-loop embolic-agent preparation device. The MCU board integrates the
UAS acoustic chain, a CV-camera trigger, two stepper actuators (TMC2209), two limit
switches, an I2C turbidity pair (APDS9960 + MAX30102), a UI breakout via 20-pin IDC,
USB-C native programming, and — new in v3.2 — a 2-channel load-cell force sensor
(HX711 x2) at the syringe contact point as a StallGuard fallback.

MCU module: ESP32-S3-WROOM-1-N4 (4 MB flash, PCB antenna, NO PSRAM). [ESP32] CORRECTED v3.3 — prior versions of this brief documented N8 (8MB); the actual module on hand is N4 (4MB). Confirmed against the datasheet that this changes nothing pin-side (see §1.3.1) — flash capacity only affects OTA partition sizing in firmware, not GPIO behavior.
A no-PSRAM variant (N4, N8, or N16 — any plain suffix without R or V) is REQUIRED, because GPIO35/36/37 are only free for the SPI
bus on non-PSRAM parts — on R8 (Octal PSRAM) variants IO35/36/37 are consumed internally
and must not be used. [ESP32, "IO35, IO36, IO37 connect to Octal SPI PSRAM and are not
available for other uses"]

1.3.1 N4 vs N8 — confirmed no pinout impact
------------------------------------------------
This board uses ESP32-S3-WROOM-1-N4 (corrected from N8 in earlier versions — see revision history). Checked directly against the module comparison table in the WROOM-1 datasheet [ESP32]: N4 and N8 share the identical die (plain ESP32-S3, no PSRAM either way) — the only difference is external flash chip capacity. Every GPIO-side fact in this document (GPIO35/36/37 free since there's no PSRAM, GPIO45/46 strapping behavior, GPIO47/48 running at 3.3V since this isn't a "V"-suffix module) applies identically to N4 and N8. Flash capacity only affects firmware OTA partition sizing, not any hardware pin assignment in this brief.

2. INPUT PROTECTION (BLOCK 1)
====================================================================================
Order of elements (source to board):
   PSU(+) → [INLINE 5x20 mm fuse, F1] → J14 screw terminal → F2 (on-board SMD backstop) →
   Q1 (reverse polarity) → D5 TVS across 24 V rail → R_LEDpwr/LED_pwr indicator →
   24 V rail (buck + motor VM bulk).

2.1 Inline fuse F1 (OFF-BOARD, PRIMARY) + on-board backstop F2 (NEW v3.4)
--------------------------------------------------------------------------
F1 (primary, off-board):
- 5x20 mm cartridge, 5 A 250 V SLOW-BLOW (time-delay, "T5A"), glass.
- Inline panel/wire holder in the +24 V lead before J14. Not a PCB part.
- Slow-blow: correct for inductive/motor inrush (a fast-blow nuisance-trips on stepper
  startup). Glass: visible blown indication, field-replaceable by hand.
- SIZING CHECK (do this): F1 carries ALL board current, not just motors. Confirm the true
  steady-state 24 V input draw. For 2x sub-1.8 A-RMS steppers the VM SUPPLY current is far
  below the coil current (the driver is a chopper: supply A ~= coil W / 24 V / eff.),
  typically ~1 A steady with the "6.5 A peak" being acceleration inrush. Keep continuous
  load <= ~75 % of the fuse rating; if real continuous draw approaches 4.5-5 A, step up to
  T6.3A. The inline holder makes this a 10-second field change — start conservative.
JUST IN CASE: keep T3.15A / T5A / T6.3A on the bench during bring-up.

F2 (NEW v3.4, on-board backstop, NOT the primary protection):
- Littelfuse Nano2 452-series Slo-Blo, 8 A, 125 VAC/VDC, 2410 (6125 metric) SMD, part
  0452008.MRL or equivalent. Placed on-board between J14 and Q1's Drain.
- DELIBERATELY sized ABOVE F1 (8 A vs F1's 5 A) so the two elements do not coordinate
  against each other in a normal motor-stall fault — F1 (lower rating, field-replaceable)
  is meant to open first every time. F2 exists only to catch the case where F1's holder is
  empty, bypassed, or mis-fitted with an oversized fuse; it is not a substitute for F1.
- Silkscreen clearly: "F2 BACKSTOP 8A — PRIMARY IS INLINE T5A" so nobody mistakes it for
  the primary protection during bring-up or field service.
- CAVEAT: distributor listings disagree on whether this Nano2 452 series is rated 125VDC
  or only 32VDC continuous — confirm against the primary Littelfuse 452/454 datasheet
  before final BOM lock, not against aggregator listings alone.

2.2 Reverse-polarity P-MOSFET — Q1 (AO4407A) + Dprot (BZX84C15)  [AO4407]
---------------------------------------------------------------------
Component | Value / part                    | Connection
-----------------------------------------------------------------------------------------------
Q1        | AO4407A, P-ch, VDS -30 V,        | Drain (pins 5-8) → F2 → J14 V+ (INPUT side).
          | VGS(max) +/-25 V, ID -12 A,      | Source (pins 1-3) → 24 V rail (LOAD side).
          | RDS(on) 13 mΩ @ -10 V, SOIC-8    | Gate (pin 4) → R_gate / Dprot junction.
R_gate    | 10 kΩ 0402                       | Gate → GND.
Dprot     | BZX84C15, 15 V Zener, SOT-23     | Cathode → Source. Anode → Gate. Clamps VGS to -15 V. (was "D7")

PINOUT (from [AO4407] p.1): Source = pins 1,2,3 ; Gate = pin 4 ; Drain = pins 5,6,7,8.
  *** This corrects the v3.1 text, which listed Gate=1 / Source=2-4. Verify the KiCad
      symbol's pin→function mapping before routing; DO NOT trust pin numbers from prose. ***

ORIENTATION (corrected v3.2): For a P-channel high-side reverse-polarity switch the body
diode (anode=Drain, cathode=Source) must be REVERSE-biased during a reverse fault so it
blocks. That requires Drain → input, Source → load (as above). v3.1 had Source→input /
Drain→load, which lets the body diode conduct a reverse fault and defeats the protection.
BENCH CHECK: power Q1 from a current-limited supply and deliberately reverse the leads — a
correct board draws ~0 mA reversed.

VGS CLAMP: at normal polarity Source sits at +24 V and Gate is pulled to GND via R_gate,
so unclamped VGS = -24 V, which exceeds a conservative rating. BZX84C15 clamps VGS to
-15 V, safely inside the AO4407A +/-25 V VGS(max) [AO4407 p.1]. The Zener also fails "off"
(gate to source), so a fault here does not release smoke.

2.3 TVS — Dclamp (SMBJ28A)
---------------------------
- SMBJ28A, unidirectional, 28 V standoff, ~45.4 V max clamp, 600 W, SMB (DO-214AA).
  *** FOOTPRINT CORRECTION: SMBJ = SMB (DO-214AA), not SMA. v3.1 listed D_SMA, which is
      the SMAJ (400 W) package. Use Diode_SMD:D_SMB for SMBJ28A, OR switch the part to
      SMAJ28A (400 W) if you keep D_SMA. Do not pair SMBJ with an SMA land. ***
- Placement: across the 24 V rail AFTER Q1 (protects the rail; reverse faults are handled
  by Q1, so the TVS never sees reverse voltage).
- MARGIN NOTE: SMBJ28A clamps at ~45 V, above the TMC2209 VM abs-max (~29-30 V, [TMC]).
  The 24 V-rail / 29 V-max window is inherently tight. If you run 24 V, confirm the PSU
  cannot overshoot/load-dump beyond ~29 V and rely on module VM bulk caps for fast
  transients. If you run 12 V, this is a non-issue (large margin).

2.4 24V power LED (NEW v3.4 — wiring closed out; parts already existed in v3.3 BOM unwired)
---------------------------------------------------------------------------------------------
LED_pwr (red 0805) + R_LEDpwr (10 kΩ 0402, NEW ref) placed AFTER Q1, tapping the PROTECTED
rail (Q1 Source — the same node D5/buck/VM bulk all tap from), not the raw input side.
Rationale: an indicator wired to raw input lights on any polarity and stays lit even if Q1
fails open, telling you nothing useful; wired to the protected rail it only lights when Q1
is actually passing current the right way — same "tells you the truth" philosophy as D7
failing safe. I = (24V - Vf~2V) / 10kΩ ≈ 2.2 mA, P ≈ 48 mW — well inside an 0805 resistor's
typical 1/8 W rating. No new non-standard value: 10kΩ is already the board's common reel.
Placement: anywhere convenient on the protected-rail side; does NOT need to be inside the
tight Q1/D7 3mm keepout (low-current DC load, no EMI/loading concern at 2.2 mA).

(Section renumbering note: all "D5" references above and below now read "Dclamp"; all "D7" now read "Dprot" — see §12.3 Master Reference-Designator Table for the full old→new cross-reference.)

WIRING GUIDE (Block 1): J14 pin1 = V+, pin2 = GND. V+ → F2 → Q1 Drain (pins 5-8). Q1 Source
(1-3) = protected 24 V rail. Q1 Gate (4) node ties R_gate (to GND) and Dprot anode; Dprot
cathode to Q1 Source. Dclamp anode to GND, cathode to 24 V rail. Protected rail → R_LEDpwr
→ LED_pwr anode; LED_pwr cathode → GND. Keep Q1/Dprot within 3 mm; wide copper on the 24 V
rail; TVS ground return short and direct.

6.5 Strapping pins
------------------
Four strapping pins: GPIO0 (boot), GPIO3 (JTAG source), GPIO45 (VDD_SPI voltage), GPIO46 (boot mode) [ESP32c]. Rules:

GPIO45 must read LOW at boot — its internal weak pull-down gives VDD_SPI = 3.3V, correct for a PSRAM-free module (N4 here). Never drive it high at reset. As of v3.3 this is the board's sole remaining spare GPIO — broken out to SP7, left unpopulated, no signal assigned. See §8.3 for why touch's IRQ line was deliberately kept off this pin rather than placed here.

GPIO46 must not read HIGH at the same moment GPIO0 reads LOW (that specific combination is invalid and triggers unexpected behavior; GPIO0 only goes low during a deliberate firmware-flash entry, not normal boot). CHANGED v3.3: GPIO46 is now T_DO (touch data out) — an ESP32-S3 *input*, driven by the touch chip only when its own CS is asserted and left high-impedance otherwise. With no external pull-up on this specific signal (see §8.3), it settles to the chip's internal weak pull-down by default and does not fight the strap read under normal conditions. Confirm on the assembled board that no accidental pull-up was added on this net before relying on this.

GPIO3 (I2C_SDA) has no internal pull; the 4.7kΩ I2C pull-up holds it high at reset. This is benign when debugging over USB-Serial/JTAG (which this board does), but confirm it does not select an unwanted JTAG source at boot.

6.6 I2C notes
-------------
SDA=GPIO3, SCL=GPIO43, 400kHz (both sensors). One pair of 4.7kΩ pull-ups to 3.3V, near U1 (shared bus, not per device). GPIO43 is UART0-TX by default in Arduino-ESP32 but the board uses USB-Serial/JTAG for all debug, so GPIO43 is free — call Serial0.end() or don't remap.

6.7 GPIO capability verification — every assignment checked against the datasheet
---------------------------------------------------------------------------------------
Requested for v3.3: a systematic re-check that every signal assigned to a pin in this document is something that pin can actually do, not just a number that happened to be free. Checked directly against the ESP32-S3-WROOM-1 and ESP32-S3 series datasheets [ESP32, ESP32c], not carried forward from memory.

Analog input (UAS_ADC, GPIO1): must be an ADC1 channel, not ADC2 — ADC2 shares hardware with the Wi-Fi radio and becomes unreliable whenever Wi-Fi is active. GPIO1 is ADC1_CH0. Confirmed correct.

Fixed-function pins (USB D+/D-, GPIO19/20): these are the native USB PHY pins and cannot be reassigned to any other function on this module — confirmed they carry no other signal anywhere in this design.

PSRAM-gated pins (GPIO35/36/37): only free for general use on a module with no PSRAM in the package. Confirmed this board's ESP32-S3-WROOM-1-N4 has no PSRAM (§1.3.1) — all three pins are legitimately available and are used for SPI_MOSI, SPI_CLK, and HX711_SCK respectively.

Strapping pins (GPIO0, 3, 45, 46): each individually addressed in §6.5. 7.1 Module specs & current  [TMC, TMCmod]
-----------------------------------------

*** CURRENT CEILING (important): with 110 mΩ sense, full-scale current is
    I_RMS = 325 mV / (R_sense + 20 mΩ) x 1/√2 = 0.325/0.130 x 0.707 ≈ 1.77 A RMS
    → 2.5 A peak MAX [TMC current equation; TMCmod]. This holds for BOTH analog-VREF and
    UART IHOLD_IRUN with I_scale_analog=0 — the sense resistor sets the ceiling. You CANNOT
    reach 2.0 A RMS / 2.8 A peak on 110 mΩ; that needs ~95 mΩ. Baseline torque and StallGuard
    tuning at ~1.77 A RMS, or source lower-Rsense modules if more torque is required. ***
Current set: firmware uses UART IHOLD_IRUN with I_scale_analog=0 for repeatability. VREF
trimpot 0-2.5 V is the analog fallback; break VREF out to a test point (SP headers) to probe.

FABRICATED-BOARD INCIDENT (v2.51 hardware, drives §7.6 below): a TMC2209 module was removed
and reinserted with the board still powered. A visible spark occurred at the socket, and the
ESP32 module has heated abnormally on every power-up since (both USB and 24V). Suspected
mechanism: the 2×8 header has no keying, so a module can seat off-axis or row-shifted for a
brief moment during a live insert — VM (24V) and coil pins share the same header block as
EN/STEP/DIR/PDN_UART, all of which trace to ESP32 GPIOs with no series impedance between the
pin and the chip prior to v3.4. A momentary bridge is enough to exceed a GPIO's internal
ESD/clamp rating. DIAGNOSIS BEFORE RE-POWERING (do not just add protection and retry):
unpowered, measure 3V3-to-GND resistance; near-zero confirms a hard short. Isolate by lifting
the ESP32 module first (short disappears → ESP32 is the failure) then working outward
section by section if it persists. Bench-test the swapped TMC module standalone before
assuming it's undamaged. Do not re-power the full board repeatedly while still isolating —
see §7.6 for the protection added in response, and §13 for the new procedural checklist line.

7.2 UART addressing  [TMC: NODEADDR = MS1(bit0), MS2(bit1)] — CHANGED v3.4: field-jumpered
-----------------------------------------------------------------------------------------
Both modules share ONE PDN bus (multi-drop, distinguished by address). Address is now
field-selectable per module instead of hardwired, making U5 and U6 fully interchangeable
spares rather than fixed-position boards.
MS1/MS2 jumpers: 1×3 header + shunt on each pin, per module (4 headers total: JMP_MS1_T1,
JMP_MS2_T1, JMP_MS1_T2, JMP_MS2_T2), same convention as JMP_U5/JMP_U6 below. Center pin =
the module's MS1 (or MS2) pad; one end = 3.3 V via a 10 kΩ pull-up (R_M1S1/R_M1S2 for
module 1's MS1/MS2 pulls, R_M2S1/R_M2S2 for module 2's); other end = GND. No shunt = pin
floats to the TMC2209's internal pull-down (safe default = 0 on that bit).
*** PULL-UP MARGIN CAUTION: MS1/MS2 have an internal pull-down inside the TMC2209 chip
    itself. An external 10 kΩ pull-up fights this internal pull-down rather than driving a
    clean logic high — the resulting voltage depends on the internal pull-down's exact
    resistance, which was not confirmed in any source checked for this document. Before
    final value lock: either measure the resulting high-level voltage on the bench against
    VIH (~0.7×VIO ≈ 2.31 V), or pull the TMC2209 Rev 1.09 DC-characteristics table for the
    exact internal pull-down value. If marginal, drop the external pull-up to 2.2-4.7 kΩ. ***
VERIFY BEFORE ROUTING: confirm which physical module pin is genuinely MS1/MS2 against the
MKS V2.0 schematic, not generic third-party SilentStepStick documentation — this project has
already found one instance (§7.3 below) where this specific module's actual silkscreen
disagreed with generic community documentation for the family.

7.3 PDN_UART — 2-GPIO TX/RX pair — *** PIN ASSIGNMENT CORRECTED v3.4, FLIPPED FROM v3.3 ***
---------------------------------------------------------------------------------------------
GPIO4 = TX, GPIO44 = RX, joined by R_UART = 1 kΩ; the junction feeds the shared PDN bus.
R_PDN_UP = 10 kΩ, PDN bus → 3.3 V (one pull-up for the whole bus).
Firmware must suppress the TX echo on RX (standard for resistor-separated half-duplex).
*** CORRECTION: physical inspection of the actual MKS V2.0 module's own silkscreen shows
    "UART" labeled at pin 5, with R8 drawn between pin 5 and pin 4 — i.e. PIN 5 IS THE
    DIRECT PDN_UART NODE and pin 4 is on the far side of the module's own separator
    resistor R8. This is the OPPOSITE of every version through v3.3, which followed generic
    third-party SilentStepStick documentation (pin 4 = direct) rather than this specific
    module's own primary-source silkscreen. Trust the physical part's own markings over
    generic community writeups for a different board in the same family — same lesson as
    the LM2596 symbol-swap finding earlier in this project. ***
DEFAULT (corrected): use the main board R_UART; connect module PIN 5 (not pin 4). Per-module
3-pin jumper (JMP_U5/JMP_U6) selects pin 5 (direct, shunt 2-1, DEFAULT) vs pin 4 (via R8,
shunt 2-3, FALLBACK) as a no-rework option if this reading is ever found to be wrong on a
given unit. Silkscreen "PDN SEL: 1=DIRECT(PIN5) / 3=VIA R8(PIN4)". Never shunt both sides.
Verify R8's actual resistance with an unpowered resistance check across module pins 4-5
before relying on the fallback path — silkscreen confirms which pin is which, not R8's value.
GPIO PROTECTION (NEW v3.4): R_gpPDN_T1 / R_gpPDN_T2 (220 Ω each) placed in series between

7.6 GPIO short-fault protection (NEW v3.4 — added directly in response to the §7.1 incident)
------------------------------------------------------------------------------------------------
A 220 Ω series resistor is now placed on every ESP32-to-TMC2209 control line, at the socket
boundary, for both modules — 12 resistors total:
  Module 1 (U5/SK1): R_gpSTEP_T1, R_gpDIR_T1, R_gpEN_T1, R_gpPDN_T1, R_gpMS1_T1, R_gpMS2_T1
  Module 2 (U6/SK2): R_gpSTEP_T2, R_gpDIR_T2, R_gpEN_T2, R_gpPDN_T2, R_gpMS1_T2, R_gpMS2_T2
PURPOSE: does not prevent a momentary bridge between VM/coil pins and a logic pin during a
mis-seated or hot-swapped module (that's a mechanical/procedural problem — see §13), but
limits the fault current that reaches the GPIO's internal ESD/clamp structure during such a
transient to something the pin can survive, rather than taking the fault directly.
ELECTRICAL IMPACT: negligible. 220 Ω into a GPIO's few pF of input capacitance gives a
sub-nanosecond RC time constant — no effect on STEP pulse timing even at high microstep
rates, and no meaningful voltage drop on EN/MS1/MS2 (near-zero static current into a CMOS
input). PDN_UART placement: in series between the shared bus and each module's
jumper-selected pin (§7.3), downstream of the existing R_UART/R_PDN_UP bus-level resistors.

8.2 Touch chip behavior on this bus
--------------------------------------
The XPT2046 shares SCK/MOSI with the ILI9341 on the same physical SPI bus and drives T_DO (MISO) only when its own CS is asserted low — otherwise it stays high-impedance, so it cannot interfere with TFT traffic when deselected. This is standard shared-bus SPI behavior, not something specific to this revision.

8.3 GPIO assignment rationale — why CS, DO, and IRQ landed where they did
------------------------------------------------------------------------------
This isn't an arbitrary pin reshuffle — it's built around one constraint: GPIO45 and GPIO46 are the board's only two strapping pins with any headroom left, and strapping pins are riskiest when an external pull resistor could be asserting a level during the boot-time strap sample.

T_CS commonly gets an external pull-up so the touch chip idles deselected before firmware configures anything — that makes it the "loudest" of the three touch signals at boot. It goes on GPIO12, freed by removing BTN2, which carries zero strapping role — so an external pull-up there is a complete non-issue.

T_DO (touch's MISO output) has no external pull-up in a typical XPT2046 wiring — the chip drives it push-pull when selected and leaves it high-impedance when not. That makes it the cleanest of the three signals, so it's the one placed on a strapping pin — GPIO46.

T_IRQ is usually open-drain with its own external pull-up (needed since it's open-drain), which makes it electrically similar to T_CS — exactly the kind of signal that risks fighting GPIO45's or GPIO46's boot-time strap read. Rather than accept that risk, T_IRQ is simply not connected on the main board as of v3.3. Touch presence is polled in firmware instead of interrupt-driven — a small, predictable firmware cost (§11.2), not a hardware risk. This also means GPIO45 stays completely unused, leaving it as the one genuinely spare, unclaimed pin on the entire board.

HX711's clock and data pins (GPIO37/42/21) are unaffected by any of this — they were never wired to the touch ribbon pins to begin with; they connect to the separate SK4/SK5 header sockets. See §10.2.

Keep the 20-pin land pattern and silkscreen identical to the breakout's mating side, since the breakout itself is unchanged.

10. LOAD-CELL FORCE SENSING — 2× HX711 (ADDED IN v3.2)
====================================================================================
Purpose: a hardware fallback for TMC2209 StallGuard SG_RESULT. Two load cells at the syringe contact/push point measure plunger force directly; if PDN_UART / SG_RESULT proves unreliable, the PID mixing-stop uses force instead. This is an independent sensing path with no UART dependency.

10.1 HX711 module facts  [HX711 datasheet, Avia Semiconductor]
-------------------------------------------------------------
Selected module: XFW-HX711 (green board, SKU MOD-BRE-007). Confirmed from the module photo: the MCU-side 4-pin header order, top to bottom, is GND, DT, SCK, VCC. The load-cell side is a 6-position screw terminal: E+, E-, A-, A+, B-, B+. An on-board RATE select is silkscreened "80Hz / 10Hz" with a 0Ω/solder-jumper between them — set this to 80Hz for force feedback (12.5ms latency vs. 100ms at 10Hz). This resolves the original "expose RATE" just-in-case item on its own, since the module already exposes it with no rework needed. Verify on a scope that DT produces ~80 samples/s once selected.

General HX711 behavior: supply range 2.6–5.5V at under 1.5mA, with a 24-bit sigma-delta ADC. It's a two-wire interface — SCK/PD_SCK is the clock in from the MCU, DT/DOUT is data out to the MCU. DT reads HIGH when the chip isn't ready and goes LOW once a sample is ready to read. A read consists of 25–27 PD_SCK pulses, where the exact count selects the channel and gain for the *next* reading: 25 pulses selects channel A at gain 128 (the default, ±20mV full-scale), 26 selects channel B at gain 32, and 27 selects channel A at gain 64.

On the XFW board, AVDD (bridge excitation) tracks VCC directly. At VCC=3.3V, a typical 2mV/V load cell produces roughly 6.6mV full-scale — comfortably inside the ±20mV gain-128 range, so 3.3V operation is fine.

Timing constraint worth building firmware around: if PD_SCK stays HIGH for more than 60µs, the chip powers itself down. A read burst must never be stalled mid-sequence by a long ISR — see §11 for how the compute budget protects this.

10.2 Wiring — XFW-HX711 modules on 4-pin sockets (SK4, SK5), shared clock
-----------------------------------------------------------------------
Each socket (SK4/SK5) matches the XFW header order GND/DT/SCK/VCC, top to bottom.

Module          |  GND  |  DT (DOUT)            |  SCK (PD_SCK)     |  VCC 
--------------------------------------------------------------------------
HX711 #1 (SK4)  |  GND  |  GPIO42 (HX711_1_DT)  |  GPIO37 (shared)  |  3.3V
HX711 #2 (SK5)  |  GND  |  GPIO21 (HX711_2_DT)  |  GPIO37 (shared)  |  3.3V

VCC is 3.3V so DT/SCK logic runs at 3.3V — direct to the ESP32, no level shifting needed. At 5V VCC, DT's high level would also be 5V and would damage the ESP32 GPIO — do not power these modules from 5V.

SCK is shared between both modules (both module SCK pins tie to GPIO37); DT is separate, one GPIO per module. Firmware clocks both chips together and reads both DT lines within the same loop — this needs a custom bit-bang driver, since standard HX711 libraries assume one dedicated clock pin per chip. Wait until both DT lines read LOW before starting a clock burst.

On the load-cell side, wire to the XFW screw terminals at E+/E- (excitation) and A+/A- (signal — channel A is the one in use). Keep load-cell leads short and twisted, and route them away from the switching regulators.

10.3 NC / spare breakout (just-in-case philosophy)
-------------------------------------------------
RATE is already exposed on the XFW board itself as the 80Hz/10Hz jumper (§10.1) — set to 80Hz, no main-board rework needed. Channel B (the B+/B- terminals, fixed gain 32) is unused and left available on the module's own screw terminal for a possible second or redundant sensor later — again, no board change required to use it if that need comes up.

WIRING GUIDE (Block 9): place SK4/SK5 near the board edge for the syringe cable run. GPIO37 (shared SCK) routes to both headers; keep the two DT lines short. The modules self-decouple; add a 100nF cap at each header's VCC pin if the specific module you receive lacks one onboard. Treat the force-sensor cable like an analog run — keep it away from the switchers and the STEP/DIR traces.

11. FIRMWARE NOTES & COMPUTE BUDGET
====================================================================================
Goal: confirm the ESP32-S3 (dual-core Xtensa LX7 @ 240MHz, ~600+ DMIPS aggregate) can run every peripheral in real time. The design leans on hardware peripherals for anything fast, so the CPU only supervises rather than bit-banging.

11.1 Core allocation
---------------------
Core 0 handles Wi-Fi + BLE (NimBLE) stack, the USB-Serial/JTAG console, and non-real-time communication (RPi UART). Core 1 handles the real-time control tasks — STEP supervision, HX711 reads, the PID mixing-stop loop, ADC sampling, and TMC UART polling. The HX711 burst is deliberately pinned to core 1 so Wi-Fi interrupts on core 0 can never stall it.

11.2 Per-peripheral load
--------------------------
STEP/DIR generation uses MCPWM, RMT, or LEDC — all hardware peripherals, never bit-banged. Worst-case example: a NEMA17 at 1/16 microstepping, 200 full steps/rev, ~600 RPM (10 rev/s) works out to 10 × 200 × 16 = 32,000 steps/s per motor. Hardware timers produce this directly; the CPU only updates a frequency register on ramp changes, which is effectively 0% CPU load. Even a naive bit-banged implementation would only cost roughly 0.3% per motor (32kHz × ~20 cycles ≈ 0.6M cycles/s) — but the point is not to bit-bang this at all; use the hardware timers.

HX711 ×2, shared clock: at 80 SPS, that's one 27-pulse burst every 12.5ms. Clocking at ~500kHz (2µs/pulse, safely under the 50–60µs power-down limit) makes each burst roughly 54µs. Per second, that's 80 × 54µs ≈ 4.3ms, or about 0.43% of one core — both channels are read within the same burst. This burst needs a short critical section so no other ISR can push PD_SCK-high past the 60µs power-down threshold mid-read.

UAS ADC (GPIO1): the envelope is already formed in analog hardware (diode + RC), so the ADC is only sampling a slow, settled envelope (~500µs settling time). A few kSPS with the on-chip ADC plus simple peak/threshold math comes in well under 1% CPU load.

TMC2209 UART (2 drivers, multi-drop): SG_RESULT and status polling at roughly 1kHz over a hardware UART routed through the GPIO matrix costs under 1%.

I2C turbidity sensing (400kHz bus, 50–100Hz sampling, hardware I2C peripheral) also costs under 1%.

TFT (SPI2 @ 20MHz, DMA): bursty during screen updates, but DMA offloads the actual transfer. Budget the refresh rate to what the UI actually needs — 5–15fps of partial updates is comfortably within a single core's headroom.

Touch (SPI, shared bus with TFT, polled rather than interrupt-driven as of v3.3 — see §8): adds one additional SPI transaction per poll cycle. Polling at, say, 60Hz costs a small fraction of a percent — negligible next to the TFT traffic it shares a bus with.

Buzzer/LED (LEDC), EC11 (edge interrupts), and the remaining button/limit switches (debounced GPIO) are all negligible.

**Aggregate: real-time load on core 1 is a few percent; core 0 handles the radios.** The ESP32-S3 has ample headroom for this full peripheral set. Two design rules keep that true going forward: (1) use hardware peripherals for STEP, SPI (TFT/touch), I2C, UART, and PWM — never bit-bang them; (2) keep the HX711 burst on core 1 and short-critical-section it so a long ISR can never stall PD_SCK-high past 60µs, which would power the HX711 down mid-read.

11.3 Key firmware settings
-----------------------------
TMC2209: set GCONF.en_spreadcycle=1 with readback confirmation, and GCONF.I_scale_analog=0 with UART IHOLD_IRUN. Suppress the TX echo on the resistor-separated PDN half-duplex bus.

SPI: ILI9341 at 20MHz, AD9833 in SPI Mode 2 (CPOL=1), touch (XPT2046) sharing the same bus at a lower clock rate appropriate to the chip, polled per §8 rather than interrupt-driven.

I2C: Wire.begin(SDA=3, SCL=43, 400kHz). APDS9960 in ALS mode at address 0x39; MAX30102 in backscatter mode at address 0x57, sampled 50–100Hz for rolling variance.

HX711: a custom shared-clock driver, selecting 80 SPS (RATE pin high) since latency matters here. Wait for both DT lines to read low before starting a burst; read 24 bits MSB-first on falling PD_SCK edges; the 25th-and-beyond pulse count sets the gain for the next reading.

EC11 quadrature decoding runs on GPIO16/17 via edge interrupts.

14. "JUST IN CASE" PHILOSOPHY (KEPT AT EVERY IMPORTANT POINT)
====================================================================================
All active complex parts sit on sockets/headers — ESP32 (module), TMC2209 ×2, AD9833, HX711 ×2 — field-replaceable, no hot-air rework needed to swap any of them.

NC/reserved IC pins are broken out to 1-pin headers to solder later if needed: TMC2209 DIAG/INDEX/VREF (SP1–SP6), HX711 RATE and channel B kept accessible on the module itself. ESP32 GPIO45 is the board's only remaining spare pin (SP7) — GPIO46 is committed to T_DO and is no longer available as a just-in-case header.

Fallbacks without rework: PDN jumpers (pin 5 direct vs. pin 4 via on-module R8 — default flipped v3.4, §7.3); MS1/MS2 address jumpers, NEW v3.4, make U5/U6 fully interchangeable spares instead of fixed-address boards; RfO1_1 is THT so Tx gain can be hand-swapped without hot-air rework (deliberately not a trimpot, to avoid accidental drift); the inline fuse F1 swaps in seconds, with F2 as an on-board backstop if F1's holder is ever empty or mis-fitted; touch runs polled rather than interrupt-driven specifically so GPIO45 stays free for whatever comes up next, rather than being spent on T_IRQ.

GPIO short-fault protection, NEW v3.4: 12× 220Ω series resistors on every ESP32-to-TMC2209 control line, added directly in response to a live hot-swap/spark incident on the fabricated v2.51 board (§7.1) — a mitigation for the specific failure mode already observed on real hardware, not a hypothetical.

Independent redundancy for the mixing-stop: TMC StallGuard SG_RESULT and HX711 force — either can drive the PID if the other proves unreliable.

Bench-verify before trusting: reverse-polarity draw ~0mA when reversed; AD9833 OUT clock alive on VCC/GND only, before trusting SPI (still not done — see §13 open items); TMC CLK-to-GND and R8 by unpowered continuity; MS1/MS2 pull-up margin against the TMC2209's internal pull-down; coil current on a scope; I2C scan confirms both 0x39 and 0x57; confirm no external pull-up landed on T_DO (GPIO46) before first power-up; PDN pin4/pin5 identity confirmed against each specific module's own silkscreen, not generic documentation for the part family.
